# Qwen3 HC-SMoE compression

This directory preserves the HC-SMoE compression layout used for
`Qwen/Qwen3-30B-A3B-Instruct-2507`, adapted from the
[official HC-SMoE repository](https://github.com/wazenmai/HC-SMoE). The
official HC-SMoE codebase in turn acknowledges
[UNITES-Lab/MC-SMoE](https://github.com/UNITES-Lab/MC-SMoE) as its codebase
foundation. See `LICENSE` for the retained third-party license.

## Data and environment

Use any dedicated conda environment for this compression method. Install a
CUDA-enabled PyTorch build for the host, the retained method requirements, and
lm-evaluation-harness `0.4.13.dev0` as documented in `common/README.md`:

```bash
ENV_NAME=beyond-moe-hcsmoe
conda create -n "$ENV_NAME" python=3.11 -y
conda activate "$ENV_NAME"
# Install a CUDA-enabled PyTorch build appropriate for the host first.
python -m pip install -r requirements.txt
cd /path/to/lm-evaluation-harness
python -m pip install -e .
```

The merge-only entry point does not call the upstream evaluator, but importing
`hcsmoe.evaluation.minipile` loads the package's retained `__init__.py`, which
imports `lm_eval`. Installing lm-evaluation-harness `0.4.13.dev0` in the same
active environment therefore prevents an import failure without changing the
original package initialization code.

Download and decompress the first English C4 training shard, then expose its
path explicitly:

```bash
export C4_DATASET_PATH=/path/to/c4-train.00000-of-01024.json
```

The expected source is
`https://huggingface.co/datasets/allenai/c4/blob/main/en/c4-train.00000-of-01024.json.gz`.
The dataset is deliberately not included in this repository.

The launchers retain `TASK=rte` because it is part of the original command
shape. Upstream HC-SMoE used `task` to select post-merge evaluation, not the
calibration dataset. That evaluation call is disabled in this merge-only Qwen3
fork, so the argument is now a no-op placeholder. It does not affect expert
grouping, merging, or output paths. The implementation constructs its
calibration loader from C4; `C4_DATASET_PATH` therefore controls the data read
by all three launchers.

## Compression runs

Run one ratio or all ratios from this directory:

```bash
C4_DATASET_PATH=/path/to/c4-train.00000-of-01024.json \
  bash scripts/qwen/run_qwen3_hcsmoe_50p.sh

C4_DATASET_PATH=/path/to/c4-train.00000-of-01024.json \
  bash scripts/qwen/run_qwen3_hcsmoe_all.sh
```

| Retention | Physical experts/layer | Output directory |
|---:|---:|---|
| 50% | 64 | `qwen3-30b-a3b-hcsmoe-50p-64e/` |
| 62.5% | 80 | `qwen3-30b-a3b-hcsmoe-625p-80e/` |
| 75% | 96 | `qwen3-30b-a3b-hcsmoe-75p-96e/` |

Each run uses eight C4 calibration blocks (`N_SENTENCES=8`), batch size 2,
expert-output similarity, hierarchical clustering with average linkage and the
silhouette stopping metric, and `zipit` merging. Runtime outputs and logs keep
their original locations under this directory. Model weights are generated by
the scripts but are not distributed in the repository.

`CUDA_VISIBLE_DEVICES` defaults to `4,5,6` and can be overridden, for example:

```bash
CUDA_VISIBLE_DEVICES=0,1,2 C4_DATASET_PATH=/path/to/c4.json \
  bash scripts/qwen/run_qwen3_hcsmoe_625p.sh
```

The `check_qwen3_hcsmoe_*.py` files validate the saved logical-to-physical
expert mapping and perform a short generation check.
